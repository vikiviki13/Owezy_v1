# shadcn/ui — Setup, Conventions & UI-Library Spec

> **Purpose of this document:** Documents exactly how **shadcn/ui** is configured and used in the **Tab** expense-tracker project, and — more importantly — contains a complete specification for building a **better, reusable shadcn-based UI library** out of it. Hand this file to ChatGPT or any design engineer to design/generate that library.

---

## 1. What shadcn/ui Actually Is

shadcn/ui is **not an npm package** you install at runtime. It is a **source-code component library**:

- Components are copied **into your repo** (not imported from a dependency), so you own and can modify every line.
- Radix UI primitives (headless, accessible) handle behavior; *you* own the styling via Tailwind classes.
- Styling is driven by **CSS variables mapped through Tailwind v4's `@theme inline`** — so one token layer themes 100% of components, with instant dark mode.
- The CLI (`npx shadcn@latest`) fetches components from a registry (`https://ui.shadcn.com/r/styles/{style}/{name}.json`) and writes them into your `components.json`-configured folder.

**Why it scales:** tokens → utilities → components → composition. Change a token, the whole library re-themes. No drift, no duplicated CSS, dark mode is free.

## 3. Token Architecture (how theming works — THE core concept)

CSS variables are declared per theme; Tailwind utilities are generated by mapping them in `@theme inline`. **The variable name is the contract; the utility is the skin.**

### 3.1 Structure in `src/index.css`

```css
@import "tailwindcss";
@import "tw-animate-css";

/* Theme 1: light */
:root {
  --background: #fbfaf7;
  --foreground: #1c1917;
  --card: #ffffff;
  --card-foreground: #1c1917;
  --popover: #ffffff;
  --popover-foreground: #1c1917;
  --primary: #059669;
  --primary-foreground: #ffffff;
  --secondary: #f4f2ec;
  --secondary-foreground: #1c1917;
  --muted: #f4f2ec;
  --muted-foreground: #a8a29e;
  --accent: #ecfdf5;
  --accent-foreground: #047857;
  --destructive: #dc2626;
  --destructive-foreground: #ffffff;
  --border: #e7e3d8;
  --input: #e7e3d8;
  --ring: #059669;
  --radius: 0.75rem;
  --radius-sm: calc(var(--radius) - 4px);
  --radius-md: calc(var(--radius) - 2px);
  --radius-lg: var(--radius);
  --radius-xl: calc(var(--radius) + 4px);
  /* anything extra: --chart-1..5, --sidebar*, custom tokens */
}

/* Theme 2: dark — same variable NAMES, different values */

  --background: #14120f;
  --foreground: #f5f4f0;

  /* … every variable overridden … */
}

/* Map variables → Tailwind utilities (used by BOTH themes) */

  --font-sans: 'Inter', ui-sans-serif, system-ui, sans-serif;
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-card: var(--card);
  --color-card-foreground: var(--card-foreground);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-secondary: var(--secondary);
  --color-secondary-foreground: var(--secondary-foreground);
  --color-muted: var(--muted);
  --color-muted-foreground: var(--muted-foreground);
  --color-accent: var(--accent);
  --color-accent-foreground: var(--accent-foreground);
  --color-destructive: var(--destructive);
  --color-destructive-foreground: var(--destructive-foreground);
  --color-border: var(--border);
  --color-input: var(--input);
  --color-ring: var(--ring);
  --radius-sm: var(--radius-sm);
  --radius-md: var(--radius-md);
  --radius-lg: var(--radius-lg);
  --radius-xl: var(--radius-xl);
  /* custom utilities follow the same pattern */
}
```

### 3.2 The rules that make it work

1. **Dark mode = toggling a single `.dark` class on `<html>`.** Every component reads variables, so no component needs its own dark styles.
2. **Never hard-code colors in components.** Components only use semantic utilities (`bg-primary`, `text-muted-foreground`, `border-border`).
3. **Custom tokens are just more variables.** Adding `--warning`, `--info`, `--success` + `@theme inline` mapping gives you free `bg-warning` utilities, dark-mode included.
4. **`--radius` produces a scale automatically** (`rounded-lg` = 12px here) — always derive from `--radius`, never hard-code `rounded-[13px]`.

### 3.3 Semantic pair rule

Every "surface color" has a **foreground pair** for text on it:

```
--background → --foreground        (page bg + body text)
--card       → --card-foreground   (card bg + card text)
--popover    → --popover-foreground
--primary    → --primary-foreground   (text ON a primary button/swatch)
--secondary  → --secondary-foreground
--muted      → --muted-foreground
--accent     → --accent-foreground
--destructive→ --destructive-foreground
```

This is how buttons render `text-primary-foreground` and change theme for free.

## 4. Component Conventions (the shape every component must follow)

Every shadcn component in `src/components/ui/` follows this anatomy (see `src/components/ui/switch.tsx` as the working example in this repo):

```tsx
import * as React from "react"
import { Switch as SwitchPrimitive } from "radix-ui"   // 1. Radix primitive
import { cn } from "@/lib/utils"                          // 2. cn() merge

function Switch({ className, size = "default", ...props }) {
  return (
    <SwitchPrimitive.Root
      data-slot="switch"                                 // 3. data-slot marker
      data-size={size}
      className={cn(
        "peer relative inline-flex items-center rounded-full …", // 4. cn(…)
        "data-[state=checked]:bg-primary",                // 5. semantic tokens only
        className                                         // 6. className passthrough
      )}
      {...props}
    >
      <SwitchPrimitive.Thumb data-slot="switch-thumb" className="…" />
    </SwitchPrimitive.Root>
  )
}

export { Switch }                                        // 7. named export (+ forwardRef-free)
```

**The 7 non-negotiables:**

1. Wrap the matching **Radix primitive** (behavior, a11y is inherited — never re-implement).
2. Use `cn()` from `@/lib/utils` — it merges Tailwind classes so consumers can override.
3. Mark every element with `data-slot="<component>-<part>"` (used by Tailwind v4 selectors and debugging).
4. All styling inside `cn(...)` as Tailwind utilities.
5. **Semantic tokens only** (`bg-primary`, `text-muted-foreground`) — ZERO hex values, ZERO `bg-[#...]` arbitraries.
6. Spread `...props` and accept `className` last so overrides win.
7. React 19 style — plain function components, named exports, no `forwardRef` needed.

**Variants** are declared with `cva()` from class-variance-authority:

```tsx
const buttonVariants = cva(
  "inline-flex items-center justify-center …",
  {
    variants: {
      variant: {
        default: "bg-primary text-primary-foreground hover:bg-primary/90",
        outline: "border border-input bg-background hover:bg-accent",
        ghost: "hover:bg-accent hover:text-accent-foreground",
        destructive: "bg-destructive text-destructive-foreground",
      },
      size: { default: "h-11 px-6", sm: "h-9 px-4", lg: "h-12 px-8", icon: "size-10" },
    },
    defaultVariants: { variant: "default", size: "default" },
  },
)
```

Prefer variant/size props over ad-hoc `className` overrides — that is how a library stays consistent.

## 5. Known Quirks When Generating Components (Windows)

1. **`shadcn init` throws "Could not load the workspace config"** after writing `components.json` — an upstream Windows bug (path-alias regex only understands `/`). The config IS written correctly; continue with `shadcn add`.
2. **`shadcn add` writes files into a stray `@\components\ui\` folder.** After every `add`, move the generated files from `@\components\ui\*` into `src/components/ui/`.
3. **Selector mismatch:** the new shadcn registry emits `data-checked:` / `data-unchecked:` selectors, but installed `radix-ui` 1.6.x emits `data-state="checked"`. Rewrite:
   - `data-checked:` → `data-[state=checked]:`
   - `data-unchecked:` → `data-[state=unchecked]:`
4. After adding a component, run `npm run build`, `npm run lint` and open the app in both light and dark mode.

## 6. Composition Patterns (what good shadcn usage looks like)

| Need | Compose with |
|---|---|
| Settings page | sticky header + `card` sections with divider rows |
| Settings toggle row | `label` + `Switch` in a card row |
| Bottom sheet / quick actions | `Sheet` (mobile) + `Dialog` (confirms) |
| Filter tabs (All / Pending / Settled) | pill buttons or `Tabs` |
| Toast feedback | `Sonner` (`sonner` package) |
| Badges on amounts | `Badge` + status tokens |
| Empty states | `Card` + icon + button (still app-specific content) |
| Avatar stacks | `Avatar` + `AvatarGroup`-style overlap with ring |
| Big money display | Card + `font-extrabold` + `font-variant-numeric: tabular-nums` |
| Loading states | `Skeleton` |

**Rule:** never hand-roll what a shadcn component already provides. Compose, don't reinvent.

## 7. Spec: The "Better UI Library" to Build From This

Use this section as the prompt input for ChatGPT to design/generate the improved library. Everything in §1–§6 is the contract it must preserve.

### 7.1 Goals

1. Drop-in replacement for the current custom components (keep app compilations working).
2. Complete **token layer**: color (light+dark), spacing, radius, typography, shadow, z-index, motion — all as CSS variables + `@theme inline` mapping.
3. Every component ships **all states**: hover, active, disabled, focus-visible, loading, error.
4. Dark mode and reduced-motion support in every single component.
5. Consistent spacing/radius/motion values matched to the product's brand assets (see `design.md` §11).

### 7.3 Token scales to define

- **Spacing:** 4px base scale (2, 4, 8, 12, 16, 20, 24, 32, 40, 48) as `--space-*`.
- **Radius:** derived from `--radius` (sm = −4px, md = −2px, lg, xl = +4px).
- **Typography:** display (hero money, 36–48px extrabold), title (20–24px semibold), heading (16–18px), body (15px), small (13–14px), caption (12px), micro (10–11px) + `tabular-nums` money class.
- **Shadow:** soft card, raised, popover, overlay; each with dark-mode pair.
- **Motion:** durations (150/220/300ms), easings (springy sheet curve `cubic-bezier(0.32, 0.72, 0, 1)`), reduced-motion fallback.
- **Z-index:** dropdown 1000 < sticky 1100 < overlay 1200 < modal 1300 < toast 1400.
- **Status colors:** success / warning / error / info + soft backgrounds, complete in BOTH themes.

### 7.4 Deliverables ChatGPT should produce

1. Full `index.css` token file (light + dark + `@theme inline`).
2. One file per component in `src/components/ui/` (radix + cva + cn + data-slot).
3. A mapping table: old custom component / ad-hoc class → new shadcn component and token.
4. Dark-mode + reduced-motion + WCAG AA contrast verification notes.
5. Optional: a `registry.json` so the CLI can install this library in future projects (`npx shadcn add` from a custom registry).

## 8. TL;DR

- shadcn = source-copy components over Radix + Tailwind v4 tokens.
- Tokens are CSS vars in `:root`/`.dark`, mapped via `@theme inline` into utilities.
- Components: Radix primitive + `cn()` + `data-slot` + semantic utilities + variants via `cva()`.
- Never hard-code colors/radius/shadows; compose instead of reinventing.
- The better library = complete token scales + state-complete components + dark-mode everywhere.
